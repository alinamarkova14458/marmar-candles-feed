# MarMar CANDLES: аудит аналитики и план собственной аналитической системы

Дата: 31.10.2026. Все цифры ниже получены через API Google (Search Console, GA4, Merchant Center) и прямыми проверками сайта. Ничего на сайте не менялось.

Главный KPI проекта — **заказы и прибыль**, а не количество отчётов. Поэтому план начинается с исправления того, что уже сейчас теряет деньги или ломает измерения. Дашборд идёт последним.

## 1. Главное (TL;DR)

1. **Падение трафика после миграции — почти целиком зарубежная аудитория молдов, а не покупатели из Латвии.** Показы в Google упали с ~8 200/мес (апрель–май) до ~2 000/мес (сентябрь–октябрь). Если разделить по странам:

   | | Показы апр–май | Показы сен–окт | Клики апр–май | Клики сен–окт |
   |---|---|---|---|---|
   | **Латвия** | 4 142 | 3 671 (−11 %) | 275 | 270 (**−2 %**) |
   | Остальной мир | 12 392 | 243 (−98 %) | 154 | 11 |

   - Зарубежный трафик шёл на **молды для свечей** (молды больше не продаются) и английские статьи блога. Запросы про молды и бенто: 1 325 показов и 45 кликов → почти 0. Pinterest приводил на молды 15–37 визитов в месяц (в основном США, Индия, Мексика, Великобритания), сейчас 3–4. За 12 месяцев с Pinterest была 1 покупка.
   - **Вывод:** для продаж в Латвии это падение почти ничего не значит. Сравнивать «до» и «после» нужно **только по Латвии и по товарам, которые продаются сейчас**, иначе любые выводы искажены.
   - Реальные потери для Латвии меньше, но они есть. Старые URL проходят через цепочки из 2–3 редиректов (в том числе через технический домен `marmarcandles.area.lv`), часть отдаёт 404. Запрос «sveces» опустился с 9-й на 18-ю позицию.
2. **Конфликт canonical.** Страница открывается по адресу `/lv/…`, а canonical на ней указывает на адрес без `/lv/`, который редиректит обратно на `/lv/…`. Google получает противоречивые сигналы. Поэтому в индексе по 3 варианта одних и тех же страниц.
3. **Сайт очень медленный на телефоне.** Lighthouse (mobile): производительность **28/100**, LCP **11,7 с**, главная страница весит **7,6 МБ**, ответ сервера 4,7 с. Это один лабораторный замер из облачного сервера, его нужно повторить. Но вес страницы — объективный факт. **70 % визитов — с телефона.**
4. **Воронку в GA4 сейчас измерить нельзя.** Нет событий `view_item`, `view_item_list` и `begin_checkout`. `add_to_cart` (13) меньше, чем `purchase` (26). **Данные событий хранятся всего 2 месяца** (настройка по умолчанию). 7 из 26 покупок (27 %) попадают в канал «Unassigned».
5. **Органический поиск — лучший канал по деньгам**:

| Канал (авг–окт) | Сессии | Покупки | CR | Выручка | € на сессию |
|---|---|---|---|---|---|
| Organic Search | 509 | 11 | 2,2 % | 233 € | 0,46 € |
| Organic Social | 966 | 3 | 0,3 % | 55 € | 0,06 € |
| Paid Social | 670 | 2 | 0,3 % | 67 € | 0,10 € |
| Direct | 764 | 1 | 0,1 % | 7 € | 0,01 € |

6. **Спрос в латышском Google небольшой** (~2 000 показов в месяц на весь сайт). Только SEO в Латвии даст ограниченный рост. Самые сильные рычаги выручки:
   - (а) конверсия: скорость сайта на телефоне, страницы, которые получают трафик, но не продают;
   - (б) бесплатные товарные объявления Merchant Center;
   - (в) Литва и Эстония.

> ⚠️ **Статистическая оговорка.** ~10 заказов в месяц — маленькая выборка. Недельные колебания почти всегда случайны. Решения принимаем по окнам 1–3 месяца и по крупным разрывам (как 0,46 € против 0,06 € на сессию), а не по десятым долям процента.

### 2.2 Почему ломается e-commerce в GA4

Сейчас события WooCommerce в GA4 отправляет **Site Kit**. Его «conversion tracking» для WooCommerce отправляет только `add_to_cart` и `purchase`, а шагов воронки нет. Кроме того, на форуме WordPress.org есть свежая (сентябрь–октябрь 2026) тема о том, что `add_to_cart` в Site Kit 1.187 не доходит до GA4. Это совпадает с нашими цифрами.

**Рекомендация:** официальный плагин WooCommerce **«Google Analytics for WooCommerce»** ([woocommerce/woocommerce-google-analytics-integration](https://github.com/woocommerce/woocommerce-google-analytics-integration), разрабатывает команда WooCommerce, последний коммит 30.10.2026). В его коде есть полный набор событий GA4 e-commerce, включая `begin_checkout` и поддержку блочной корзины и оформления заказа. Альтернатива — **GTM4WP** (GPL-3.0, активен), но он требует настройки Google Tag Manager и избыточен для одного человека.

⚠️ **Риск двойного учёта:** Site Kit и второй плагин могут оба отправлять `page_view` или `purchase`. Порядок такой: сначала проверить на тестовой копии сайта (или в окно с низким трафиком) и сверить с Realtime и DebugView. Ничего не ставлю без согласования.

Независимо от GA4: в WooCommerce (с версии 8.5) есть встроенная **Order Attribution**. Она сохраняет источник визита (organic / utm / referral) прямо в заказе. Если она включена, канал каждого заказа берём из WooCommerce. Это надёжнее GA4: не зависит от блокировщиков. Проверю, когда будет ключ REST API.

### 2.4 Миграция Mozello → WordPress: что потеряно

| Старый URL (Mozello) | Показы / клики апр–май | Сейчас | Ценность для продаж |
|---|---|---|---|
| `/blog-2/params/post/…/best-birthday-candles-for-cake` и ещё 5 англ. статей | ~11 000 / ~70 | 301 → **404** | низкая: зарубежная информационная аудитория |

| `/veikals/category/svecites-tortem-un-kukam/` | 776 / 65 | 301 → `marmarcandles.area.lv` → 301 → `/lv/…` → 200 (**цепочка через технический домен**) | **высокая** |
| `/veikals/category/tortes-un-kucinu-toperi/` | 332 / 26 | та же цепочка | **высокая** |
| `/veikals/category/ziemassvetku-sveces/svecites-tortem-un-kukam/` | — | 301 → **404** | **высокая** (сезон) |
| `/veikals/item/…/bisu-vaska-ciparu-svece-6…` | — | 3 редиректа подряд, потом 200 | средняя |

Старые URL молдов не нужно «спасать» ради трафика. Достаточно одного 301 на ближайшую живую страницу (например, курс или главную), чтобы не было 404.

Технический домен `marmarcandles.area.lv` открывается с `index, follow`. Canonical там правильный, но он всё равно не должен участвовать в редиректах.

## 4. Рекомендуемый стек (всё бесплатно)

| Слой | Выбор | Почему |
|---|---|---|
| Запуск по расписанию | **GitHub Actions** в приватном репозитории | Уже используется для фида. В бесплатном плане 2 000 минут в месяц для приватных репозиториев, нам нужно ~100 |

| Скорость | **Unlighthouse** (раз в месяц, все страницы) + **PageSpeed API** (раз в неделю, 5 ключевых URL, полевые данные) | Лаборатория + реальные пользователи |
| Хранилище | **DuckDB** + Parquet-файлы в приватном репозитории | Без сервера. История сохраняется навсегда, в отличие от 16 месяцев в GSC |
| Аналитический слой | SQL-модели в DuckDB | Одно место для формул KPI, не размазано по отчётам |
| **Главный результат** | **Еженедельный отчёт «что делать»** (Markdown или GitHub Issue): ответы на 7 бизнес-вопросов и 3 действия на неделю | Отвечает на вопрос «что изменить», а не просто показывает цифры |
| Дашборд | **Evidence** → статический сайт с закрытым доступом (например, Cloudflare Pages + Cloudflare Access, бесплатно для небольшой команды — уточню условия перед настройкой) | Можно смотреть с телефона, без сервера |

## 5. Архитектура

```
             ┌───────────── приватный репозиторий marmar-analytics ─────────────┐
             │                                                                  │
 GitHub      │  collectors/ (Python, раз в сутки ночью)                         │
 Actions ───▶│   gsc.py      → Search Console: дата × страница × запрос × страна│
 (cron)      │   ga4.py      → GA4: каналы, лендинги, события воронки, товары   │
             │   woo.py      → WooCommerce: заказы, позиции, товары, категории  │
             │                 (имена/адреса/телефоны НЕ сохраняются,          │
             │                  e-mail → необратимый хэш для повторных покупок) │
             │   merchant.py → статусы товаров, ошибки фида                     │
             │                                                                  │
             │  audits/ (раз в неделю / месяц)                                  │
             │   crawl.py (advertools) · lychee · unlighthouse · PageSpeed API  │
             │                                                                  │
             │  data/  *.parquet  →  marmar.duckdb                              │
             │  models/ SQL: orders, order_items, sessions_by_channel,          │
             │          funnel, gsc_pages, product_perf (+ costs.csv)           │
             │                                                                  │
             │  reports/weekly-YYYY-WW.md  ← ответы на бизнес-вопросы + 3 шага  │
             │  dashboard/ (Evidence) → статический сайт за паролем             │
             └──────────────────────────────────────────────────────────────────┘
                     ▲ read-only ключи в GitHub Secrets (никогда в коде)
```

**Как связываются источники**
- **URL страницы:** приводится к одному виду (без `www.`, без `/lv/`, без хвостового `/`). Так склеиваются GSC (клики/показы) ↔ GA4 (лендинги, покупки) ↔ краулер (title, H1, скорость).
- **Товар:** ID WooCommerce (`wc_<id>` в Merchant Center, `item_id` в GA4).
- **Заказ ↔ канал:** WooCommerce Order Attribution (основной источник), GA4 — для сверки.
- **Деньги** берутся только из WooCommerce. GA4 видит ~84 % заказов.
- **Сегменты рынка во всех отчётах:** Латвия / Литва / Эстония / остальной мир. Отдельный справочник `discontinued.csv` — снятые с продажи товары и темы (молды, материалы для свечей). Их трафик исключается из сравнений «до/после», чтобы старая аудитория Pinterest не искажала выводы.

**Определения KPI**

| KPI | Формула | Источник |
|---|---|---|
| Organic Traffic | клики GSC; сессии Organic Search | GSC, GA4 |
| Organic Revenue | сумма заказов с атрибуцией organic/google | WooCommerce (сверка с GA4) |
| Conversion Rate | заказы / сессии (по каналу, по лендингу) | WooCommerce + GA4 |
| AOV | выручка / заказы (с доставкой и без) | WooCommerce |
| Revenue per Product | сумма по позициям заказов | WooCommerce |
| Gross Margin | (цена − себестоимость − упаковка) × кол-во | WooCommerce + `costs.csv` |
| Add-to-Cart Rate | сессии с `add_to_cart` / сессии с `view_item` | GA4 (**после исправления трекинга**) |
| Checkout Abandonment | 1 − покупки / сессии с `begin_checkout` | GA4 (**после исправления**) |
| Repeat Purchase Rate | клиенты с ≥2 заказами / все клиенты | WooCommerce (хэш e-mail) |
| SEO Performance | клики, показы, CTR, позиция; число запросов в топ-10 | GSC |
| Тех. здоровье | 404, цепочки редиректов, страницы без title/H1, LCP | краулер, Lighthouse |

**Себестоимость.** В WooCommerce есть встроенное поле «Cost of Goods Sold» (функция ядра, появилась в 2025 году). Проверю, доступна ли она в вашей версии. Если нет или если удобнее, ведём простую таблицу `costs.csv` по категориям: воск, фитиль, краска, упаковка, минуты работы. Точности по категориям хватит, для 251 товара по отдельности это не нужно.

**Как система отвечает на бизнес-вопросы**

| Вопрос | Как отвечаем |
|---|---|
| Почему не покупают? | Воронка `view_item → add_to_cart → begin_checkout → purchase` по устройствам + скорость лендингов |
| Трафик без продаж | Лендинги: сессии GA4 + клики GSC при 0 заказах за 90 дней |
| Товары с высоким спросом | Просмотры товара, добавления в корзину, продажи, показы в Merchant Center |
| Запросы, которые приводят покупателей | GSC не связывает запрос с заказом напрямую. Связка запрос → лендинг (GSC) → заказы лендинга (WooCommerce/GA4) |
| Где теряются клиенты | Шаг воронки с наибольшим падением, отдельно для мобильных |
| Технические ограничения | Еженедельный дифф краулера: новые 404, редиректы, сломанный canonical |
| Что даст максимальный эффект | Оценка «потенциальные клики × CR лендинга × AOV × маржа» для каждой задачи |

**Предварительные ответы (по данным сегодняшнего аудита)**

**Принципы безопасности**
- Все ключи только для чтения. Ключи хранятся только в Secrets и никогда не выводятся в логи.
- Персональные данные покупателей не сохраняются: имя, адрес и телефон отбрасываются при загрузке, e-mail превращается в хэш с секретной «солью». Это нужно для GDPR и на случай утечки репозитория.
- Версии GitHub Actions закреплены, зависимости Python — с фиксированными версиями (защита от подмены пакетов).
- Публичный репозиторий `marmar-candles-feed` остаётся только для фида товаров.
