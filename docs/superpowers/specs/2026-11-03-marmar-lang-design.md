# Плагин переводов MarMar Lang — описание (черновик на утверждение)

Дата: 03.11.2026. Статус: **ждёт «ок» Алины**. Код не пишется до утверждения.

## Зачем
- Бесплатно заменить GPTranslate: сейчас Google видит на `/en/…` латышский текст (перевод делается в браузере) и считает эти страницы дублями.
- Языки: **lv** (основной), **en** — первым, затем **lt** и **et**, когда появятся заказы из Литвы и Эстонии.
- Переводы делает и обновляет Claude через API; Алина может посмотреть и поправить их в админке. Никакого ручного ввода по умолчанию.

## Что увидит покупатель и Google
- Адреса: латышский — как сейчас без префикса (`/product/…`), английский — `/en/product/…`, литовский — `/lt/…`, эстонский — `/et/…`. Адреса товаров в v1 остаются с латышскими «хвостами» (`/en/product/ciparu-svece-5/`), переводные адреса — во второй версии.
- На каждой странице: переведённые название, текст, короткое описание, SEO‑заголовок и описание, `<html lang>`, правильный canonical на свой язык, метки `hreflang` для всех языков.
- Переключатель языка в шапке и в мобильном меню.
- Корзина, оформление заказа, письма о заказе — на языке покупателя (официальные бесплатные языковые пакеты WooCommerce + Loco Translate для недостающих фраз). Язык заказа запоминается в заказе.
- Карта сайта для каждого языка — для Search Console.
- Если перевода у товара ещё нет — страница на этом языке **не создаётся** (нет пустых/латышских дублей), ссылка в переключателе ведёт на латышскую версию.

## Где хранится перевод
- **В той же записи**, в отдельных полях: товар, категория, страница, статья, пункт меню получают поля `EN / LT / ET` (название, текст, короткое описание, SEO‑заголовок, SEO‑описание). Латышский текст не трогается.
- Поля доступны через REST API — так Claude записывает переводы пачками.
- В админке у товара/страницы — блок «Tulkojumi» с этими полями, чтобы Алина могла поправить.
- Если плагин выключить, сайт просто остаётся латышским; ничего не ломается и не «вылезает».

## Из чего состоит (модули)
1. **Языки и адреса** — определяет язык по префиксу, переключает язык WordPress/WooCommerce, добавляет префикс ко всем внутренним ссылкам.
2. **Контент** — подставляет переводы в названия, тексты, категории, меню, атрибуты (цвета), Store API корзины.
3. **SEO** — hreflang, canonical, `lang`, переводы для Rank Math, карты сайта по языкам, `noindex` для страниц без перевода.
4. **Админка и API** — поля «Tulkojumi», регистрация полей в REST, страница настроек (какие языки включены).
5. **WooCommerce** — язык корзины/оформления/писем, язык заказа.

## Перенос с GPTranslate
- Сейчас латышские страницы доступны по трём адресам (`/lv/…`, без префикса, `www.`). После переезда: основной — без префикса, `/lv/…` → 301 на него, `www.` → 301.
- `/en/…` остаются теми же адресами — Google сохранит позиции, но начнёт видеть настоящий английский текст.
- GPTranslate отключается в тот же день (оплачен разово, отменять нечего).

## Проверка до установки
- Тестовая копия WordPress + WooCommerce + Blocksy + Rank Math в контейнере Claude: автотесты на адреса, переводы, корзину, оформление заказа, письма, hreflang/canonical, LiteSpeed‑кэш.
- На живом сайте — сначала в скрытом режиме (видно только администратору), затем включение.
- **Срок включения: январь 2027**, после рождественского пика. Резервная копия перед установкой.

## Что не входит в v1
- Переводные адреса товаров (`/en/product/number-candle-5/`) — v2.
- Разные цены/валюты по странам.
- Автоматический машинный перевод.

## Риски
- Новая часть сайта: в первые недели возможны мелкие непереведённые фразы (особенно в корзине и письмах). Решение: тестовая копия, скрытый режим, проверка Claude после включения.
- Обновления WooCommerce/темы могут потребовать правок плагина — поддержку делает Claude, код в репозитории.
